# 材料承认助手

熔断器原材料承认流程的状态登记工具。用来回答三个问题：

- 哪个批次走到哪了
- 下一步做什么
- 今天该去哪个场地

不是替代实验记录本。测试数据仍然记在测试本上，这个工具只管状态。

## 它是什么

一个单文件网页应用，没有任何依赖、不用联网、没有后端。

打开 `index.html` 就能用。数据存在浏览器本地的 localStorage 里，不上传任何服务器。

主要功能：

- **今日看板** —— 异常（漏项 / 停滞）排最上面，然后是待判定、进行中、待承认
- **场地视图** —— 按楼栋楼层聚批，一个地方要做的活一次列全
- **测试项登记** —— 开始 / 合格 / 待判定 / 不合格 / 本批免做，点一下就行
- **重新送样** —— 不承认之后回到接样，送样次数 +1，上一轮结果存进历史
- **「其他」品类** —— 对不上现有九类的新物料走这条：写个物料名称，手动勾测试项，现场还能加自定义实验（自动存进字典，以后每次都能选）
- **导入导出** —— CSV 批量导入历史批次，随时导出备份
- **回收站** —— 删掉的批次先放回收站，可以恢复，确认不要了再永久删除

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 整个应用（HTML + CSS + JS 都在里面） |
| `sw.js` | service worker，提供离线访问 |
| `manifest.webmanifest` | 让手机能"添加到主屏幕" |
| `icon.svg` | 图标 |
| `_headers` | Cloudflare Pages 的响应头设置 |
| `404.html` | 404 页面 |
| `robots.txt` | 禁止搜索引擎收录 |

## 本地打开

直接双击 `index.html` 即可。

想用离线缓存（service worker），需要走 HTTP，在所在目录跑：

```
python -m http.server 8765
```

然后打开 `http://127.0.0.1:8765/`。

## 部署

纯静态站点，任何静态托管都能用：Cloudflare Pages、GitHub Pages、对象存储都行。

**如果部署到 Cloudflare Pages**：构建命令留空，输出目录留空（`index.html` 就在根目录）。

**注意**：`*.workers.dev` 域名在中国大陆无法访问（DNS 污染）。要让链接在国内可用，需要绑定自己的域名。

改了 `index.html` 之后，记得把 `sw.js` 里的 `VERSION` 加一，否则访客可能还在用旧的离线缓存。

## 数据

数据只存在每台设备自己的浏览器里，不会同步。换设备或清理浏览器数据之前，先到「导入导出」页导出 CSV。

数据结构是"字典表"而不是"表格列"：测试项和物料的对应关系存成一张对应表，加测试项只加一行，不用改结构。

#### 核心数据表

- `物料品类` —— 9 个主类 + 5 个变体
- `测试项字典` —— 16 个测试项，各自带所属类别、场地
- `品类-测试项对应` —— 哪个物料要做哪些项
- `批次` —— 批次号、品类、供应商、采购、送样日期、送样次数、承认结论
- `批次测试项` —— 一个批次有几个必做项就有几行，状态流转在这里
- `送样历史` —— 不承认后重新送样时存快照

进度、当前节点、承认结论、异常标记全部由系统算出来，不需要手工维护。

## 规则

- 超期阈值 2 天，超过就标记为停滞
- 有测试项做完了但前面的还没做 → 标记漏项
- 有测试项处于"待判定"→ 批次不出承认按钮，防止漏判
- 承认结论只有两个：承认 / 不承认。不承认 → 重新送样
